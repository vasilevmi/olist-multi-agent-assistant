# Проверка качества через DeepEval

В этой папке находится контрольный набор вопросов для проверки мультиагентной системы.

Все оценки выполняются библиотекой **DeepEval**. Старый самописный запускатель
удалён, чтобы в проекте оставался один актуальный механизм проверки.

## Что находится в папке

- `cases.json` — контрольные бизнес-вопросы и ожидаемые результаты;
- `deepeval_suite/adapter.py` — преобразует результат нашего приложения в формат DeepEval;
- `deepeval_suite/judge.py` — подключает нашу LLM как модель-судью DeepEval;
- `deepeval_suite/metrics.py` — задаёт стандартные метрики DeepEval и их пороги;
- `deepeval_suite/test_agents.py` — запускает приложение и передаёт результат на оценку;
- `reports/` — актуальные структурированные отчёты последнего запуска.

Контрольный набор содержит два типа кейсов:

- `deterministic` — вопросы, для которых заранее известны нужные инструменты и факты;
- `research` — исследовательские вопросы, где проверяются полнота, обоснованность и качество вывода.

## Перед запуском

Активируйте виртуальное окружение и установите зависимости:

```powershell
venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

В `.env` должны быть настроены `LLM_API_KEY`, `LLM_BASE_URL` и `LLM_MODEL`.
Также должны быть доступны PostgreSQL и загруженный набор данных Olist.

## Как запускать

Один конкретный кейс:

```powershell
deepeval test run evaluation/deepeval_suite/test_agents.py -k D001
```

Только детерминированные кейсы:

```powershell
deepeval test run evaluation/deepeval_suite/test_agents.py -m deterministic
```

Только исследовательские кейсы:

```powershell
deepeval test run evaluation/deepeval_suite/test_agents.py -m research
```

Все кейсы сразу:

```powershell
deepeval test run evaluation/deepeval_suite/test_agents.py
```

Для последовательного запуска с понятным структурированным отчётом используйте
проектный запускатель:

```powershell
python -m evaluation.run_deepeval
```

Один кейс с записью отчёта:

```powershell
python -m evaluation.run_deepeval --case D001
```

Только исследовательские кейсы с записью отчёта:

```powershell
python -m evaluation.run_deepeval --mark research
```

После каждого завершённого кейса запускатель обновляет два файла:

- `evaluation/reports/deepeval_results.json` — полный машиночитаемый отчёт;
- `evaluation/reports/deepeval_results.md` — удобный отчёт для человека.

В отчётах сохраняются статус кейса, оценки, пороги, причины решений DeepEval,
ошибки, вызванные инструменты и время работы приложения. Благодаря сохранению после
каждого кейса уже полученные результаты не потеряются при прерывании полного прогона.

## Что происходит при запуске

Для каждого кейса система:

1. отправляет вопрос основному приложению;
2. Orchestrator выбирает специализированных агентов и инструменты;
3. агенты получают факты через MCP;
4. Critic формирует итоговый ответ;
5. адаптер собирает весь видимый пользователю ответ (краткий ответ, основные
   факторы и следующие проверки), Evidence и вызовы инструментов в `LLMTestCase`;
6. DeepEval запускает свои метрики и выставляет оценки;
7. кейс считается успешным, только если пройдены все назначенные ему метрики.

Важно: один тест расходует вызовы LLM не только на работу агента, но и на работу
LLM-судьи. Исследовательские кейсы дороже, потому что для них используется больше
метрик.

Подробное описание оценок находится в [METRICS.md](METRICS.md).
